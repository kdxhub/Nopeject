# 2026-11-08

## Nopeject 首个版本实现

- 技术栈：SwiftPM 零依赖，Swift 6.3 + SDK 26.5（macOS 26.5.1）
- 架构：`NopejectCore`（模型/IPC/安全通道/枚举器）+ `NopejectDaemon`（DiskArbitration 拦截）+ `NopejectApp`（SwiftUI MenuBarExtra 前端）
- 提交：`f8805ed`（Neonai 身份）；注意本地 main 与 origin/main 已分叉（1 vs 1），未处理远程同步
- 关键验证结果：
  - IPC 握手（uid + HMAC-SHA256 挑战-应答）、getMountPoints、setConfig/getConfig 持久化、断连重连全部通过探针测试
  - 真实拦截验证：保护 KIOXIA-1TB 后 `diskutil eject` 被拒（exit 1），解除保护后配置恢复
- 踩坑记录（已沉淀为 skill `swiftpm-macos-daemon-menubar`）：
  - CLT 环境无 `Crypto` 模块 → 自实现 SHA-256/HMAC
  - DiskArbitration Swift 桥接：回调签名 `(DADisk, UnsafeMutableRawPointer?) -> Unmanaged<DADissenter>?`，注册需传 `nil` matching 字典；拒绝状态用 `DAReturn(kDAReturnNotPermitted)`（此 SDK 无 kDADissenterApproval）
  - `swift build` 在沙盒内需 `--disable-sandbox`
  - Unix socket 服务端必须每连接独立 dispatch，否则长连接会阻塞 accept
  - SwiftPM 可执行产物名 = product name（NopejectApp → Nopeject）
  - `statfs.f_mntfromname` 是 tuple，需 withUnsafeBytes 读 C 字符串
  - CF 类型 downcast 用 `unsafeDowncast(x as AnyObject, to: CFUUID.self)`

## 后续修正：过滤内置系统盘

- 用户反馈：Macintosh HD 等内置宗卷本就无法推出，无需保护
- 修改 `MountEnumerator.enumerate()`：过滤「internal 且不可弹出」的宗卷（系统盘、内置数据卷），仅保留外置/网络卷
- 实测枚举结果只剩 KIOXIA-1TB、WD-1TB-HDD，Macintosh HD 已隐藏

## 实机复验（仅 WD-1TB-HDD）

- 拦截：保护 WD UUID 后 diskutil eject 被拒绝，diskutil 报告 dissenter 为 nopejectd ✅
- 解除后推出成功 ✅；保护状态下 ejectOnce 临时弹出成功 ✅
- 发现并修复缺陷：ejectOnce 字符串负载存在「JSON 引号包裹 vs 裸 UUID」两种形式，
  守护进程改为 `decode(as: String.self) ?? message.data` 兼容两者
- 协议注意点：广播事件（blocked）会与请求应答在同一连接上交错，接收端必须按 action 分发
- 测试后 WD-1TB 已重新挂载，配置已清空
